“AI in Organizations” workshop · Session 3 · Sepehr Co. (fictional company)

Solution Architecture Canvas

Fill in the ten cells below for one concrete solution. Each cell has a guiding question — if an answer is unclear, write exactly that; an unnamed empty cell is a hidden risk.
Model & AI role Human role Data & knowledge Risk & control

1. User

Who uses the solution and in what role? How many people?

2. Channel

Where does the interaction happen? Team chat, portal, email, inside an existing system?

3. Model

Small or large model? Cloud or on-premises? What limits do you place on output?

4. Knowledge

Where do answers come from? Which sources are allowed? Which repository does RAG connect to?

5. Rules

What must the model never say or do? What is the rule for citing sources and declining out-of-scope requests?

6. Tools

Which systems does the solution connect to? Is each connection “read only” or “write/act”?

7. Access

Who manages permissions and under which policy? Can a user only reach their own data?

8. Event log

What gets recorded (question, source, answer, decision)? Who can audit it?

9. Human confirmation

Which outputs need human approval before sending or executing? Who approves?

10. Failure path

If a source is unavailable, the model is unsure, or a system is down — what happens? What is the human fallback?

Short worked example (Session 3 VPN scenario):
  • User: all 800 Sepehr employees; channel: team chat.
  • Model: large cloud model under a no-training data policy; knowledge: the IT guide repository, restricted to 120 approved documents.
  • Rules: every answer must cite a document; out-of-scope = refer to a specialist.
  • Tools: read from the document space; write to the ticketing system only with user confirmation.
  • Human confirmation: the ticket draft is shown to the user before filing; failure path: if no guide is available, reply “no documented answer” + manual ticket creation.
